## Done
- Lines slider turned arrows and thermos blue (Nov 22) — done in v43: above 100, near-grey strokes (arrows #9ca3af, thermos #c8ccd2, kropki, and any other low-chroma or very dark line) go to full opacity and darken toward black with no hue shift (desaturate and mix toward #000). Coloured lines (renban purple, whisper green) still saturate as in v42. Below 100 still fades. Defaults still match v40.
- Visuals pane tweaks (Nov 22) — done in v42: ☰ menu buttons are all the same size and colour, with Visuals at the bottom. Pencil-mark outlines were invisible on split-colour cells because v33 set `--halo` to transparent (and 2× was too thin on small marks). Mark halos are now always white; a shared Marks outline opacity slider (0–100%, default 60) sets their alpha; width at 200 is 5× the v40 stroke (100 stays the default). Placed-digit outline max is 4×. Lines strength above 100 now saturates each line’s own colour and raises opacity, instead of darkening to black. Defaults still match v40 on uncoloured cells. .nh chips and CR1 .nh2 unchanged.
- Visuals pane for live tuning (Nov 22) — done in v41: the ☰ UI contrast slider is now a Visuals button, which opens a bottom sheet of sliders that stays below the grid and updates it live. Corner and centre marks each have darkness and outline; cages have darkness; one Lines strength slider covers arrows, thermos, whispers, renbans and dots; placed digits have outline; UI contrast lives in the same pane. Defaults (100) reproduce v40, including the size-based centre-mark colour ramp (the darkness slider moves both ends of the ramp). Outline sliders scale halo width (0–2×, 60% alpha unchanged). Values persist in localStorage; Reset to defaults is included. .nh chips and CR1 .nh2 are unchanged.
- Centre-mark blend should follow font size, not count (Nov 20) — done in v40: 1–4 centre marks share the unshrunk 26cqh size, so they stay the old #374151. Colour then mixes toward #222 in proportion to how much the font has shrunk, reaching 100% at the 6-digit size (19cqh) and staying there for 7+ (16cqh). The mix is computed in CSS from the same `--mn-size` used for `font-size`, so the two cannot drift. Corner marks are a fixed 23cqh, so they keep the halfway mix. Weight, renban #dd9ff3, halos, .nh chips and CR1 .nh2 are unchanged.
- Large pencil marks too dark (Nov 20) — done in v39: centre-mark colour starts at the old #374151 for one digit and blends linearly to #222 at six or more (`color-mix` by (n−1)/5). Corner marks are a fixed halfway mix of those two colours. Weight stays 400. Renban #dd9ff3, halos, .nh chips and the CR1 grey-bold corner twin (.nh2) are unchanged.
- Pencil marks pale on renbans (Nov 20) — done in v38: David picked darker marks only (cr7 option B: #222, weight stays 400; weight 600 was too thick) plus the slightly lighter renban from option D (#dd9ff3, opacity still 0.8). Halos, .nh amber chips and the CR1 grey-bold corner twin (.nh2) are unchanged.
- Cage sums overlapping the dashed cage (Nov 20) — done in v37: v33 gave `#lines` a z-index of 4, above `#grid` (auto), so the white rounded cage-sum label — still in the CSS, still in the top-left corner — was painted under the dashed cage and other lines. In v28 those SVG layers had no z-index, so the label sat on top and covered the corner. Sums now render in a `#sums` layer at z-index 5, above the lines. Background, position, padding and radius are unchanged. Halo z-order and stroke are unchanged. WebKit 390 crops of the 5, 13 and 15 cages are pixel-identical to v28.
- Long centre-mark halo and placed-digit thickness (Nov 20) — done in v36: David picked option C from the cr6 mockup. Halo stroke now scales with each text’s font size (`calc(1.7em / 26)` for marks, so a 6-digit centre string is thinner than the old fixed 1.7cqh; placed digits use `calc(1.5em / 66)` ≈ 1.5cqh) and is the cell colour at 60% opacity. Long strings like 23456 / 234567 no longer get a heavy border as they shrink, and the big-digit gap is closer to the approved v28 look. `paint-order: stroke fill` keeps the glyph weight. Split-colour cells still use a transparent `--halo`. Z-order unchanged.
- Placed-digit halo still too thick (Nov 20) — done in v35: David asked for half the v34 border. Placed-digit stroke is 2.25cqh (was 4.5cqh); pencil marks stay at 1.7cqh.
- Placed-digit halo thickness (Nov 20) — done in v34: David picked 4.5cqh from the cr5 mockup. v33’s 7cqh text-stroke cut a wider gap than the approved v28 option B halo. Placed digits now use 4.5cqh; pencil marks stay at 1.7cqh.
- Split-colour white ring and ghost 3 on placed-digit halos (Nov 20) — done in v33: v32 painted a background-coloured text-stroke on `#ink` above every line layer, and fell back to white on a multi-colour cell, so the 2 on the teal/pink split had a visible white ring (and the stroke also cut a 3-shaped hole in the thermo, leaving a grey ghost 3 in the open bowls). `#ink` now sits above arrows and renbans only, and below thermos and whispers, so those layers multiply over the digits again (the v28 look: no painted ring on a bulb or a pie). Split-colour cells use a transparent stroke, so the halo cannot be a white ring. Yellow 5, orange 4, grey circle fills, dimming, and given/user/error colours are unchanged. Stroke on a plain white cell is still invisible.
- Placed-digit halo alignment (Nov 20) — done in v32: v31 still cut arrow/renban lines around placed digits with an SVG `<text>` mask, which sat to the left of the real HTML digit on iOS Safari (same font/baseline mismatch as the v30 mark bug). Placed digits now use the same `#ink` HTML text-stroke as the marks, at the approved v28 thickness (7cqh), coloured to match the cell (white, dimming, solid colour). Given/user/error colours and highlight glow are unchanged. Stroke on a plain cell is the cell colour, so it is invisible when no line runs behind the digit.
- Pencil-mark halo alignment (Nov 20) — done in v31: v30 cut arrow/renban lines with a second SVG `<text>` mask for pencil marks, which did not match iOS Safari’s HTML font, baseline or letter-spacing, so white “ghost” digits sat beside the real marks. Marks are now painted in an `#ink` layer above the lines as the same HTML, with a thin background-coloured text-stroke (option B look). Placed digits keep the approved SVG-mask halo, still on arrows and renbans. Thermos and whispers themselves are unchanged; marks sit above them so they also get a clean gap.
- Pencil-mark halo (Nov 20) — done in v30 (option B from cr4-mockup): corner and centre marks get a thinner hard cut (~1/3 of the v29 note width) in arrow and renban lines. Placed digits keep the approved v28 halo thickness, now also applied on renbans. Thermos and whispers stay whole.
- Highlight bug (Nov 20) — done in v29: a centre mark of the highlighted digit always gets the amber chip. v28's `.map(noteMark)` passed the digit's index as the “weak” flag, so a 3 that was not first in the centre marks (e.g. 1234) was only bold/grey. A corner mark still gets the amber chip unless the same cell also has that digit as a centre mark, in which case the corner twin stays grey bold.
- Pencil-mark halo (Nov 20) — done in v29: the CR2 digit-shaped gap in arrow lines (option B, subtle) now also cuts around corner and centre pencil marks, not only placed digits.

- CR2 (Nov 20) — done in v28 (option B, subtle halo): arrow lines and heads are cut away in a thin digit-shaped gap round every placed digit, so the real cell background (white, colours, split colours, dimming) shows round the digit. Thermos, whispers and renbans are left whole.
